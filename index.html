Why Binary Search Is So Fast

Imagine looking for a page in a 1,000-page dictionary. Checking page 1, page 2, page 3 (Linear Search) takes up to 1,000 steps. Opening straight to page 500 and tearing the wrong half away (Binary Search) finds any page in at most 10 steps because 2¹⁰ = 1,024!

LOW Left boundary of the remaining search window
MID Middle element currently being compared with target
HIGH Right boundary of the remaining search window
FOUND Target locked or element placed in final sorted index
Pro C++ Tip: Always write mid = low + (high - low) / 2 instead of (low + high) / 2 so large indices never overflow a 32-bit signed int!

How to Connect Supabase or Firebase Later (Zero Backend Server Required)

Because GitHub Pages hosts static HTML/CSS/JS files for free, it doesn't run a database server by itself. When you're ready to share a live leaderboard with your C++ community, you can connect a free Supabase (PostgreSQL) or Firebase project in ~20 lines of JavaScript:

1. Create a `profiles` Table

Columns: id (uuid), username (text), xp (int4), quests_done (int4), streak (int4).

2. Enable GitHub OAuth Login

Use supabase.auth.signInWithOAuth({ provider: 'github' }) so learners sign in with their GitHub account.

3. Replace `demoLeaderboard`

Fetch top 20 learners with supabase.from('profiles').select('*').order('xp', { ascending: false }).limit(20).
